## 設計重點與痛點拆解

一般 Claude Code 使用者（即使不會寫程式碼）最常遇到的三大痛點與行為改變：
1. **對話式頻繁打斷（非系統彈窗，而是模型一直在文字對話中停下問）**：明明交代了「全部改，中間不用過問我」，模型改了 3 個檔又停下來問「接下來可以嗎？該怎麼做？」。
2. **重度批次工作塞爆主對話**：大批次抽取、分類、查核直接在主線硬幹，不僅主視窗被刷爆，還迅速耗盡每週昂貴的 Claude 額度。
3. **收尾旁生枝節、一直發散**：準備收工時，模型常常冒出「還有一件事要提醒你...」、「要不要順便重構 CSS？」等無關建議，旁生枝節，反而把真正需要人拍板的決策項淹沒。

短片以此設計六幕精確對照（每幕 10 秒，共 60 秒，節奏充裕便於閱讀）：

| 幕次 | 時間 | 畫面主題 | 擬真終端機操作示範 | 核心訊息 |
|---|---|---|---|---|
| **01** | 0.0s - 10.0s | Auto 痛點（前） | `Claude Code (default)`<br>交代不用問，模型改 3 個檔仍停下問「接下來該怎麼做？」 | 用 Claude Code 最累：一直停下來問 |
| **02** | 10.0s - 20.0s | Auto 解法（後） | `> /work-mode auto`<br>本機可回復步驟放手一次做完，測試全過零對話打擾 | auto 模式：本機可回復，不再對話打斷（金流、刪除才問） |
| **03** | 20.0s - 30.0s | Out 解法 | `> /work-mode out`<br>分類 1,000 筆用戶回饋，外派背景子代理，主線僅驗收 | out 模式：大批工作外派，省下 20%+ 主額度 |
| **04** | 30.0s - 40.0s | Wrap 痛點（前） | `Claude Code (default)`<br>準備收工，模型不斷提醒「測試覆蓋率低」、「要不要重構 CSS」等無關話題 | 準備收工時：模型開始旁生枝節（越想收工越收不了） |
| **05** | 40.0s - 50.0s | Wrap 解法（後） | `> /work-mode wrap`<br>拒絕旁生枝節，收斂輸出【待你決定】決策清單與具體建議 | wrap 模式：拒絕旁生枝節，聚焦決策（安心下班） |
| **06** | 50.0s - 60.0s | 模式統整 | `> /work-mode auto out wrap`<br>自由組合三種工作節奏，掌控 AI 自主與專注度 | 一個指令，隨時掌握 AI 工作節奏 |

## 一鍵重算

```bash
./promo/build.sh
```

由 `vidkit` (`vk`) 與 `hyperframes` 自動化完成音樂裁剪（60 秒淡入淡出）、版面組裝、渲染、廣播級雙通道響度標準化（LUFS -12.9, True Peak -2.3 dBTP）、交付 QC 檢查，以及 720p 輕量化 README 示範與封面壓制。
